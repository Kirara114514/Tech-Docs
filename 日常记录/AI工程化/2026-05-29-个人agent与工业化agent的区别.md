## 内容

发现公司全面推行 AI 之后，并没有给出特别深度特别优秀的用法指导。会上那些积极分子的分享，在我看来都是"新兵蛋子"级别，这不太应该。后来翻了公司 AI 相关的文档才发现，其实技术高层考虑了很多，只不过有些设想太复杂，落实到每个个人可能难以完美执行。

这个问题在大厂很熟悉——**工程化**。我们在要求同事做一件事时，这件事必须有较高的**可执行性**和**可维护性**，这样才能让整个团队稳定产出，不然掺杂过多变量，产出就有风险。

在 AI 编程时代也是如此。我在反思：我们那些管理个人 agent 的技巧，是否并不适用于搭建工业化大型项目的 AI 辅助开发体系？甚至，**我们的刻板印象和既有知识可能变成负资产**——影响快速学习新版本的 agent 管理体系。

### 具体例子

**个人 agent 风格：** 直接喂代码 → 上下文爆满 → token 高消耗 → 性能下降。

**工业化 agent 思路：** 构建 skill 体系。
- 一个模块对应一个 skill（只记录调用链、实现方式、结构规范）
- 项目层面用一个"开发 skill"索引各模块 skill + 全局 skill（编码规范、分支选取等）
- agent 维护模块时调 skill 而非直接读源码

但这依然不够——对大体量项目来说，tokens 价格贵，大量上下文填充影响 LLM 注意力。**能 work，但不是最优方案。**

## 初步思考

问题核心：个人 agent 追求灵活性和单次任务效果，工业化 agent 追求**可维护性、可复用性、成本可控**。两者目标不同，方法论也应该不同。

当前 AI 编程领域的讨论大多集中在前者（"怎么让 agent 更好地帮我写代码"），后者（"怎么搭建一个团队可维护的 AI 辅助开发体系"）几乎没看到系统性的讨论。
