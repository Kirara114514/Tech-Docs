# 子 Agent 与主 Agent 的差异与执行质量探讨

## 内容

观察到的一个现象：把任务交给 spawn_subagent（子 agent）来做，相比主 agent 直接执行，完成质量明显更高。由此引发了一个核心问题——子 agent 和主 agent 的区别到底是什么？

直觉上，"差异"首先来自于上下文。主 agent 在一个会话中持续累积上下文，prompt 文件、工具调用历史、对话历史都在膨胀。子 agent 通过 spawn 启动时，上下文是"干净的"或"受控的"（取决于 fork 参数）。这种上下文纯度是否就是质量差异的来源？

另外几个未明确的问题：

1. 子 agent 启动时，prompt 配置（AGENTS.md / SOUL.md / PROFILE.md / MEMORY.md）是否与主 agent 保持一致？还是复制了某一部分？
2. spawn_subagent 的 fork 模式与非 fork 模式具体有什么区别——fork 模式是继承了父 agent 的 session state？那"继承"了什么？
3. 子 agent 是不是拥有同样的工具集？
4. 质量提升是来自于上下文纯度（减少干扰），还是来自于子 agent 有更强的"专注力"（单任务聚焦），还是纯粹的心理作用？

## 初步思考

从直觉上分析，可能有以下几个因素：

- **上下文干净：** 主 agent 的会话历史里可能混杂了无关的对话、之前任务的残余信息，这些对当前任务反而是噪声。子 agent 启动时不受这些噪声干扰。
- **任务聚焦：** spawn 本身就是一个"请你专注做这件事"的指令，这种显式的任务边界可能影响输出质量。
- **prompt 一致性：** 如果子 agent 共享同一套 prompt 文件（AGENTS.md 等），那"谁在执行"理论上应该没区别。但如果子 agent 受限于只能读 prompt 文件而无法"回忆"历史对话，那可能会在需要跨会话上下文的任务中表现更差。

## 待讨论点

3. 如果子 agent 质量确实更高，是否应该默认把复杂任务 spawn 出去做？
4. 主 agent 和子 agent 用的是同一个模型还是可配置的？
5. 这种现象是否只在特定模型（如当前使用的模型）下成立？
