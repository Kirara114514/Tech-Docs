归档前与审阅 Agent 做了三轮交叉审阅（提问／追问／收束），对原稿做了实质修正：

1. 原语从"五个名词归并成一个"修正为**两个**——动作一：决定给模型看什么文本；动作二：决定把模型的输出变成什么后果。tool use 的差异在输出侧的结构化解析与副作用执行，不在输入侧。
2. **上下文压缩被重新定性为"有损替换"**，不是注入——它具有破坏性，会改变后续循环的基态。
3. **MCP = tool use 的传输层 + 动态能力发现**，代价是框架多出「工具集同步」职责。
4. 补上了原讨论的空白：**输出侧**（输出解析与容错、输出路由与终止、工具执行）。路由与终止被合并为同一决策的两面，是排障第二高频区。
5. system prompt 做了**补偿型／结构型二分**：权威性声明是补偿型（会随模型变强过期），身份与权限语义是结构型（长期存在）。
6. token 被定为**成本的计量单位**，不单独成节，并入"预算"度量衡；成本是双向的（输入 + 输出 + 循环次数）。
7. 明确三处需要主动限定范围的表述，避免被读成技术断言：结构化 tool call 与"文本进文本出"的关系、"窗口有成本"而非"窗口有限"、两个动作是决策类型而非全部执行步骤。

## 关键收获

1. **一个循环、两个动作**是全篇的骨架：功能清单是无限的，决策类型是有限的——功能是决策的实例，决策稳定得多。
2. **排障四问**把"猜框架"变成"看文本"：这一轮实际送进去的文本是什么 → 谁决定送这些的 → 模型输出被解析成了什么副作用 → 结果怎么回灌的。黑箱感大多来自跳过第一问。
3. **纯文本直觉会漏掉五件事**：投喂顺序携带信息、触发者不同（框架自动 vs 模型请求）、两份真相（磁盘上存的 ≠ 这一轮送进去的）、副作用不可逆、预算双向。
4. **添砖分两层，过期性不同**：约定层（prompt 模板、skill 注入规则、压缩触发条件、tool 协议、MCP 传输）可无限加，但多半在迁就"模型现在还不够强"，容易过期；系统层（持久化、调度、权限沙箱、可观测、幂等回滚）在处理外部世界的三项硬性质——状态会丢、世界是并发的、副作用不可逆——不会过期。
5. **喂工作资料的本质**：在有限的投喂预算下，让每一轮真正进到模型眼里的文本信息密度最高。位置决定成本（恒常投喂 vs 按需检索投喂）；能被检索到比写得好更重要（存在性优先于质量）；压缩有损且不可逆，关键信息必须有"被压缩掉之后还能取回"的通道。
6. **过期判据**：这台机器只依赖两条事实——模型只吃文本／只吐文本、窗口有上限且有成本。真要退化成历史弯路，得等接口层变化（模型能直接读写外部状态，或窗口大到免费）。
